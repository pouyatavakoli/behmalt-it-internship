## نمای کلی

این صفحه دو موضوع مرتبط را پوشش می‌دهد: **اتاق سرور** فیزیکی و الزامات محیطی و ساختاری آن، و زیرساخت **Windows Server** درون آن، شامل Active Directory و سرویس‌های مرتبط.

## استانداردهای اتاق سرور

### مفاهیم

یک اتاق سرور برای عملکرد قابل‌اعتماد سخت‌افزار به شرایط محیطی کنترل‌شده نیاز دارد، از جمله:

* **کنترل دما و رطوبت**، معمولاً از طریق سیستم‌های HVAC یا تجهیزات خنک‌کننده مناسب، برای جلوگیری از گرمای بیش از حد و کاهش خطرات ناشی از رطوبت، تراکم و الکتریسیته ساکن.

* **کاهش خطر حریق (Fire Hazard Mitigation)**، شامل استفاده از مواد مناسب و در محیط‌های حرفه‌ای، سیستم اطفای حریق متناسب با تجهیزات الکتریکی و الزامات محل.

* **کابل‌کشی ساختاریافته** درون اتاق (به [شبکه](../fa/it-environment/network/) مراجعه کنید).

* **کنترل دسترسی** برای محدود کردن ورود فیزیکی به پرسنل مجاز (به [امنیت](../fa/it-environment/security/) مراجعه کنید).

### در به‌مالت

کارآموزی استانداردهای اتاق سرور را به‌صورت مفهومی پوشش داد، شامل الزامات مربوط به دما، رطوبت، سازمان‌دهی کابل، ملاحظات خطر حریق و کنترل دسترسی به اتاق سرور به‌مالت. استانداردهای عددی خاص، مانند محدوده دقیق دما و رطوبت هدف، در یادداشت‌های کارآموزی ثبت نشده‌اند.

## سرورهای فیزیکی و مجازی‌سازی

### مفاهیم

سرورهای فیزیکی سازمانی معمولاً با هدف **redundancy** و کاهش اثر خرابی اجزای منفرد طراحی می‌شوند. ویژگی‌های رایج شامل موارد زیر هستند:

* **اجزای Hot-Swappable** — برخی اجزای سرور مانند فن‌ها، پاورها و هارد دیسک‌ها در سیستم‌های سازگار می‌توانند بدون خاموش کردن سرور تعویض شوند.

* **RAID (Redundant Array of Independent Disks)** — چند دیسک فیزیکی را در یک آرایه منطقی ترکیب می‌کند تا بسته به سطح RAID، افزونگی، تحمل خرابی و/یا عملکرد بهبود یابد. در سطوح دارای افزونگی مانند RAID 1، RAID 5، RAID 6 و RAID 10، آرایه می‌تواند خرابی یک یا چند دیسک را طبق ویژگی‌های همان سطح RAID تحمل کند.

  آرایه‌های RAID معمولاً با دیسک‌های هم‌ظرفیت و هم‌نوع ساخته می‌شوند. استفاده از دیسک‌های با ظرفیت متفاوت در برخی پیکربندی‌ها ممکن است، اما ظرفیت قابل استفاده می‌تواند بر اساس کوچک‌ترین دیسک محدود شود؛ بنابراین استفاده از دیسک‌های مشابه یک رویه متداول است.

* **SnapRAID** — یک راهکار مبتنی بر parity برای حفاظت از داده است که بیشتر برای storage poolهای شخصی، خانگی یا آرشیوی مناسب است. برخلاف RAID سنتی، داده‌ها را به‌صورت بلادرنگ stripe نمی‌کند و parity معمولاً به‌صورت دوره‌ای به‌روزرسانی می‌شود. این ویژگی امکان استفاده از دیسک‌هایی با اندازه‌های متفاوت را فراهم می‌کند، اما به معنی ارائه redundancy بلادرنگ RAID نیست.

* **iLO (Integrated Lights-Out)** — فناوری مدیریت out-of-band سرورهای HPE است که امکان دسترسی و مدیریت سخت‌افزار از راه دور را مستقل از سیستم‌عامل فراهم می‌کند. قابلیت‌هایی مانند کنسول از راه دور، کنترل برق، مانیتورینگ و هشدارهای سخت‌افزاری از طریق iLO در دسترس هستند. iLO رابط شبکه و تنظیمات IP مستقل خود را دارد. اطلاعات اولیه دسترسی یا رمز عبور iLO، بسته به نسل و مدل سرور، معمولاً روی برچسب یا اطلاعات همراه سرور ارائه می‌شود.

* **مجازی‌سازی سرور (ESXi)** — **ESXi** محصول VMware و یک hypervisor از نوع bare-metal است که مستقیماً روی سخت‌افزار سرور نصب می‌شود و امکان اجرای چندین ماشین مجازی مستقل را فراهم می‌کند.

* **vCenter / vSphere** — **vSphere** پلتفرم مجازی‌سازی VMware است که ESXi و اجزای مدیریتی مرتبط را شامل می‌شود. **vCenter Server** ابزار مدیریت متمرکز چندین host ESXi و ماشین‌های مجازی آن‌ها است. vCenter Server معمولاً به‌صورت **vCenter Server Appliance (VCSA)**، یعنی یک appliance مبتنی بر VM، مستقر می‌شود.

### در به‌مالت

* سرورهای فیزیکی به‌مالت عمدتاً از برند **HP/HPE** هستند.

* سرورها با در نظر گرفتن redundancy استفاده می‌شوند. برخی **فن‌ها و هارد دیسک‌ها** در سیستم‌های سازگار قابلیت تعویض بدون خاموش کردن سرور را دارند و هارد دیسک‌ها در آرایه‌های **RAID** قرار گرفته‌اند تا خرابی یک دیسک، در صورت پشتیبانی سطح RAID مورد استفاده، باعث از دست رفتن داده نشود.

* **SnapRAID** به‌عنوان یک فناوری متفاوت برای حفاظت از داده و storage pool مورد بحث قرار گرفت که امکان استفاده از دیسک‌هایی با ظرفیت‌های متفاوت را فراهم می‌کند و بیشتر برای سناریوهای backup، آرشیو یا storage غیرتولیدی مناسب است.

* **iLO** رابط اصلی مدیریت out-of-band برای سرورهای فیزیکی HP/HPE است. یکی از مراحل اولیه راه‌اندازی سرور، **تخصیص یک آدرس IP به iLO** برای دسترسی مدیریتی از طریق شبکه است. اطلاعات اولیه دسترسی، بسته به مدل و نسل سرور، روی برچسب یا مستندات همراه دستگاه ارائه می‌شود.

* **ESXi** به‌عنوان لایه مجازی‌سازی روی سرورهای فیزیکی به‌مالت استفاده می‌شود. در محیط مورد بررسی، **storage بوت ESXi از آرایه RAID مورد استفاده برای داده‌های VM جدا نگه داشته شده است**. سپس **Windows Server** به‌عنوان ماشین مجازی روی ESXi اجرا می‌شود.

* به‌دلیل وجود **چندین host ESXi**، از **vSphere/vCenter** برای مدیریت متمرکز محیط مجازی‌سازی استفاده می‌شود. این ساختار امکان مدیریت چندین host و ماشین مجازی را از یک نقطه فراهم می‌کند.

* **vCenter Server Appliance** نیز به‌عنوان یک ماشین مجازی اجرا می‌شود و در محیط مورد بررسی روی یکی از hostهای ESXi میزبانی شده است.

### درس‌های آموخته‌شده

* RAID برای تحمل خرابی دیسک طراحی شده است، اما استفاده از دیسک‌های مشابه از نظر ظرفیت و مشخصات، مدیریت و بهره‌وری آرایه را ساده‌تر می‌کند. SnapRAID در مقابل، انعطاف بیشتری در استفاده از دیسک‌های متفاوت دارد، اما redundancy آن بلادرنگ نیست.

* جدا نگه‌داشتن storage بوت hypervisor از storage داده‌های VM می‌تواند به تفکیک نقش‌ها و مدیریت بهتر storage کمک کند.

* مدیریت out-of-band مانند **iLO** برای مدیریت و بازیابی سرورهای فیزیکی، حتی زمانی که سیستم‌عامل در دسترس نیست، اهمیت دارد.

* استفاده از **vCenter/vSphere** امکان مدیریت متمرکز محیط‌های دارای چندین host ESXi را فراهم می‌کند و نیاز به مدیریت مستقل هر host را کاهش می‌دهد.

## Windows Server

### مفاهیم

**Windows Server** سیستم‌عامل سروری مایکروسافت است که برای میزبانی سرویس‌های زیرساختی، شبکه و directory در محیط‌های سازمانی استفاده می‌شود. نقش‌ها و سرویس‌های مرتبط شامل موارد زیر هستند:

* **Active Directory (AD)** — مجموعه سرویس‌های directory مایکروسافت که برای مدیریت متمرکز هویت، کاربران، کامپیوترها و منابع یک domain استفاده می‌شود.

* **DNS** — نام‌های host و سرویس‌ها را به آدرس‌های IP تفکیک می‌کند و معمولاً بخش مهمی از زیرساخت Active Directory است.

* **DHCP** — به‌صورت خودکار آدرس‌های IP و سایر تنظیمات شبکه را به کلاینت‌ها اختصاص می‌دهد. این نقش می‌تواند در محیط‌های دیگر، برای مثال توسط MikroTik، نیز ارائه شود؛ به [شبکه](../fa/it-environment/network/) مراجعه کنید.

* **FTP** — سرویس انتقال فایل که در برخی محیط‌ها برای انتقال فایل استفاده می‌شود.

* **Certificate Authority (CA)** — برای صدور و مدیریت گواهی‌های دیجیتال، از جمله گواهی‌های مورد استفاده سرویس‌های داخلی.

* **Windows Time Service** — سرویس همگام‌سازی زمان در محیط Windows است. همگام بودن زمان سیستم‌ها برای عملکرد صحیح احراز هویت مبتنی بر Kerberos در Active Directory اهمیت دارد.

* **Hyper-V** — hypervisor مایکروسافت برای اجرای ماشین‌های مجازی روی hostهای فیزیکی.

* **KMS (Key Management Service)** — سازوکاری برای فعال‌سازی متمرکز محصولات ویندوز و برخی محصولات Microsoft در محیط سازمانی.

* **Server Manager** — کنسول مدیریتی Windows Server برای مدیریت نقش‌ها، ویژگی‌ها و برخی تنظیمات سرور.

### Active Directory / Domain

یک **domain** محیطی برای مدیریت متمرکز هویت و منابع شبکه است، در حالی که در یک **workgroup** هر دستگاه حساب‌های محلی و تنظیمات امنیتی خود را به‌صورت مستقل مدیریت می‌کند.

عضویت در domain امکان استفاده از **احراز هویت متمرکز، Group Policy و مدیریت منابع** را فراهم می‌کند. برای مقایسه Domain و Workgroup به [امنیت](../fa/it-environment/security/) مراجعه کنید.

درون Active Directory:

* **Active Directory Users and Computers (ADUC)** کنسول استاندارد برای ایجاد و مدیریت اشیاء کاربر و کامپیوتر است.

* **Group Policy** به مدیران اجازه می‌دهد تنظیمات پیکربندی و امنیتی را به‌صورت متمرکز روی ماشین‌های عضو domain اعمال کنند.

* منابعی مانند **پرینترها** می‌توانند از طریق سرویس‌های اشتراک‌گذاری و مدیریت متمرکز در اختیار کاربران domain قرار گیرند.

* اشتراک‌گذاری فایل می‌تواند از یک **Shared Folder** ساده تا زیرساخت‌های اختصاصی مانند **SAN** و **NAS** متغیر باشد. استفاده از FTP نیز به نیاز و معماری سرویس بستگی دارد.

* در محیط‌های بزرگ‌تر، می‌توان از راهکارهایی مانند **WSUS** برای مدیریت و توزیع متمرکز به‌روزرسانی‌های Windows استفاده کرد.

### در به‌مالت

کارآموزی موارد زیر را پوشش داد:

* نقش‌های Windows Server شامل **Active Directory، DNS، DHCP و FTP** و استفاده از **Server Manager** برای مدیریت نقش‌ها.

* پیکربندی و مفهوم **همگام‌سازی زمان** در سیستم‌های عضو domain.

* عملکرد **Certificate Authority** روی Windows Server.

* **Hyper-V** به‌عنوان نقش مجازی‌سازی موجود در Windows Server.

* **KMS** برای فعال‌سازی متمرکز محصولات Windows.

* مدیریت Active Directory از طریق **ADUC**، شامل مفهوم **عضویت در domain**.

* یک رویه امنیتی مهم: استفاده نکردن از حساب داخلی **Administrator** برای فعالیت‌های روزمره مدیریتی و استفاده از یک حساب مدیریتی جداگانه و نام‌گذاری‌شده. در صورت امکان و پس از بررسی وابستگی‌های محیط، می‌توان حساب داخلی Administrator را نیز غیرفعال کرد.

* آشنایی با گزینه استفاده از یک **سرور توزیع به‌روزرسانی** مانند WSUS برای محیط‌های بزرگ‌تر.

* **اشتراک‌گذاری پرینتر** در محیط Windows.

* گزینه‌های اشتراک‌گذاری فایل، از یک پوشه ساده به‌اشتراک‌گذاشته‌شده تا زیرساخت اختصاصی **SAN** یا **NAS**.

### درس‌های آموخته‌شده

* استفاده از یک حساب مدیریتی نام‌گذاری‌شده و اختصاصی به‌جای استفاده روزمره از حساب داخلی Administrator، یک رویه پایه برای کاهش ریسک حساب‌های privileged است.

* سرویس‌های متمرکز مانند **AD و DNS** سربار مدیریتی را کاهش می‌دهند و امکان مدیریت یکپارچه کاربران، سیستم‌ها و سیاست‌ها را فراهم می‌کنند.

* همگام بودن زمان سیستم‌ها برای عملکرد صحیح احراز هویت **Kerberos** و در نتیجه Active Directory اهمیت اساسی دارد.

## بخش‌های مرتبط

* [شبکه](../fa/it-environment/network/) — MikroTik می‌تواند در برخی معماری‌ها به‌عنوان DHCP Server استفاده شود.

* [امنیت](../fa/it-environment/security/) — کنترل دسترسی فیزیکی به اتاق سرور، Firewall/UTM شامل Fortinet / FortiGate، pfSense و Kerio، و مدل دسترسی Domain در برابر Workgroup.

* [سخت‌افزار](../fa/it-environment/hardware/) — سخت‌افزار سرور نصب‌شده در رک و تجهیزات مرتبط.
